# 무설정 장중 자동 리서치 운영 설계

## 목표와 사용자 경험

사용자는 조건식, 종목 유니버스, 기간, 수수료, 실행 주기를 설정하거나 로그인할 필요가 없다. 서비스는 매 거래일 자동으로 실제 시장 데이터 수집을 시도하고, 고정된 시스템 정책으로 조건식 후보를 생성·평가·모의 추적·선발한다. 화면에는 오늘의 실행 상태, 실제 데이터로 확인된 후보, 생존 조건식, 모의 성과와 검증 근거만 나타난다.

> 이 설계는 주문을 생성하거나 전송하지 않는다. 모의 추적은 실제 수집 데이터의 가격 스냅샷만 사용하며, 데이터가 없거나 인증이 실패하면 성과를 추정·보간·예시로 채우지 않고 해당 실행을 안전하게 대기 또는 실패 상태로 기록한다.

## 고정 시스템 정책

| 항목 | 자동 정책 | 사용자 입력 |
|---|---|---|
| 초기 유니버스 | 키움 거래대금 순위에서 수집 가능한 상위 유동성 종목 | 없음 |
| 조건식 후보 | 중첩 AND·OR·NOT 및 10~20개 규칙의 중복 없는 유전자 | 없음 |
| 초기 탐색 규모 | 웹 배치 기준 최대 100개 후보를 반복 세대로 확장 | 없음 |
| 비용·체결 가정 | 시스템 버전으로 보존된 수수료·슬리피지·다음 봉 체결·정보 절단 | 없음 |
| 생존 기준 | 인샘플 적합도, 독립 OOS, 반복 워크포워드, 낙폭·거래 수 제약 | 없음 |
| 모의 결과 | 실제 수집 가격 스냅샷으로만 진입·추적·마감 평가 | 없음 |

## 장중 자동 수명주기

자동 작업은 상시 실행 환경에서 동작하더라도 인프로세스 타이머를 사용하지 않는다. 플랫폼이 호출하는 주기 작업이 한국 거래 시간인지 판별하고, 동일 시각 재시도에도 중복 결과가 생기지 않는 `runKey`로 상태를 보존한다. 거래 시간과 자동 처리 상태는 항상 한국 표준시를 기준으로 기록하되, 데이터베이스 시각은 UTC로 보관한다.

| 단계 | 한국 시간 | 자동 작업 | 데이터 없거나 OAuth 실패 시 |
|---|---:|---|---|
| 준비 | 08:50–09:00 | 전일 결과 마감, 실행 레코드 생성, 데이터 연결 상태 확인 | `waiting_for_data` 기록 후 종료 |
| 개장 | 09:00–09:10 | 유동성 유니버스 수집, 일봉 원본 고정, 후보 생성·초기 평가 | 다음 주기까지 대기, 주문 없음 |
| 장중 | 09:10–15:20 | 실제 가격 스냅샷으로 모의 포지션과 후보 근거 갱신 | 마지막 정상 스냅샷 보존, 성과 추정 금지 |
| 마감 | 15:20–15:40 | 생존자 선발, 독립 OOS·워크포워드 집계, 일일 결과 확정 | `incomplete`로 확정하고 누락 사유 표시 |

## 활성 예약 작업

플랫폼 예약 작업은 UTC 6필드 cron으로 등록되어 있으며, 핸들러가 한국 거래 시간을 재확인하므로 비거래 시간의 호출은 안전하게 건너뛴다. 두 작업 모두 플랫폼 작업 신원으로만 `/api/scheduled/autonomous-research`를 `POST` 호출한다.

| 이름 | 작업 ID | UTC cron | 한국 시간 역할 |
|---|---|---|---|
| `aureum-autonomous-prepare` | `6nupz6iU4U4McMmzSwWsm5` | `0 50 23 * * 0-4` | 평일 08:50 개장 준비 |
| `aureum-autonomous-market` | `eqjPHhyL8kDXSNkwszckhX` | `0 */5 0-6 * * 1-5` | 평일 09:00–15:40, 5분 간격 장중·마감 추적 |

예약 실행은 후보별 실제 가격 관찰과 모의 성과를 추가할 수만 있고, 주문·계좌·자금 이동 API를 호출하지 않는다.

## 상시 실행 연속 워커 확인

프로젝트 호스팅은 **Reserved Hosting**으로 전환되어 단일 서버 프로세스가 유지되는 전제다. 서버 기동 시 `startAutonomousResearchWorker()`가 시작되며, 60초 간격으로 같은 멱등 실행 키를 사용해 자동 리서치 파이프라인을 호출한다. 개발 서버 기동 로그에서는 `[AutonomousResearch] continuous worker started (60000ms)`를 확인했다.

운영 배포 로그 조회는 현재 배포 식별자가 제공되지 않아 로그 도구에서 `deployment id is empty`를 반환한다. 따라서 운영 로그를 통한 이중 확인이 가능해지는 시점에는 위 시작 로그와 `waiting_for_data` 또는 데이터 수집 결과를 추가로 확인한다. 작업 스케줄 두 개는 워커가 재시작되거나 일시적으로 중단된 경우에도 동일한 `runKey`로 안전하게 복구 호출하는 보조 경로다.

## 실행 안전과 멱등성

자동 작업 호출은 사용자 로그인이 아니라 플랫폼 작업 신원으로만 허용한다. 외부 브라우저는 결과 조회 API만 사용할 수 있고, App Key·Secret·OAuth 토큰·예약 작업 제어권은 서버 외부로 반환하지 않는다. 각 단계는 `tradingDate:phase:minute` 단위의 `runKey`를 선점해, 플랫폼 재시도나 서버 재시작이 같은 스냅샷·후보·모의 결과를 중복 저장하지 못하게 한다.

키움 OAuth 또는 시세 요청이 8050, 자격 증명, 빈 응답, 일시적 네트워크 오류로 실패하면 단계별 상태와 원인만 기록한다. 읽기 요청은 정해진 재시도 정책을 따르되, 실패를 근거 없는 시장 수치나 모의 성과로 대체하지 않는다. 주문 API는 이 자동 리서치 경로에서 호출하지 않는다.

## 결과 전용 화면

로그인·로그아웃·운영자 메뉴·조건식 편집기·수동 실행 버튼·파라미터 폼은 사용자 화면에서 제거한다. 단일 결과 화면은 아래 정보를 공개하며, 실제 데이터가 없을 때에는 모든 수치를 빈 상태로 표시한다.

| 영역 | 표시 내용 |
|---|---|
| 오늘의 자동 실행 | 거래일, 단계, 마지막 정상 수집 시각, 데이터 연결 상태 |
| 모의 후보 | 실제 스냅샷이 있는 후보 종목, 조건 충족 근거, 점수 |
| 생존 조건식 | 규칙 수, 논리 구조 요약, 세대, 지문, 변이 계보 |
| 성과 검증 | 인샘플, 독립 OOS, 워크포워드, 장중 모의 상태와 누락 사유 |

## 데이터 연결 전 동작

지정 단말 인증이 성공하기 전에는 자동 작업이 `waiting_for_data` 상태로 종료된다. 이때도 대시보드는 자동 운영이 준비됐음을 보여 주되, 종목명·가격·수익률·랭킹·승률 같은 시장 결과를 가공해 표시하지 않는다. 인증이 성공하면 다음 주기부터 별도 설정 없이 수집·평가를 재개한다.
