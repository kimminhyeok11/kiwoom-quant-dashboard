# 키움 운영 API 연동 경계

## 구현된 REST 어댑터

이 애플리케이션은 **운영 도메인**을 기본값으로 사용하며, App Key·App Secret·계좌번호는 서버 환경 변수에서만 읽습니다. 브라우저와 상태 API에는 비밀값을 반환하지 않고, 자격 증명 가용 여부·지정 단말 허용 여부·주문 전송 가능 여부만 노출합니다.

| 기능 | API/어댑터 | 현재 안전 경계 |
|---|---|---|
| OAuth 접근 토큰 | `POST /oauth2/token` | 서버 캐시·만료 전 재발급·지정 단말 미검증 시 차단 |
| 일봉 차트 | `ka10081` | 응답을 `DailyBar`로 정규화, 빈 응답은 평가·백테스트 차단 |
| 계좌 평가·잔고 | 계좌 평가 어댑터 | 지정 단말 인증 전에는 브로커 호출 전 차단 |
| 주문 전송 | `kt10000` 매수 주문 어댑터 | 최종 확인·킬 스위치·금액·횟수·원자적 선점·별도 전송 승인 모두 필요 |
| 주문·체결 기록 | 주문 실행 기록·계좌 동기화 | 운영자 소유 주문 의도에 연결된 기록만 조회 |

## 어댑터 실행 정책

연구 데이터 경로는 `KiwoomClient`와 `KiwoomRealtimeSession`으로 분리한다. REST 어댑터는 OAuth 토큰을 서버 메모리에만 캐시하고, `ka10081` 일봉과 `ka10032` 거래대금 순위처럼 **멱등인 읽기 요청**에는 토큰별 최소 200ms 간격을 적용한다. HTTP 408·429·5xx 또는 전송 단계의 일시적 네트워크 실패가 발생하면 읽기 요청만 최대 3회까지 200ms, 400ms 간격으로 재시도한다. 최종 응답이 성공이 아니거나 키움의 `return_code`가 0이 아니면 오류를 그대로 표면화하며, 빈 일봉은 실데이터 없음으로 처리한다.

| 경로 | 재시도·재연결 정책 | 연구 데이터 계약 | 금지 경계 |
|---|---|---|---|
| OAuth `POST /oauth2/token` | 재시도하지 않음. 8050·자격 증명 오류는 즉시 기록 | 토큰이 있어야 다음 읽기 경로로 진행 | 브라우저 노출, 실패 후 임의 대체 토큰 |
| `ka10081` 일봉 | 공유 요청 조절기 뒤에 제한적 읽기 재시도 | 조정 기준·버전·유니버스에 고정한 `DailyBar` 원본만 저장 | 빈 응답을 예시 시세로 대체 |
| `ka10032` 거래대금 순위 | 제한적 읽기 재시도 가능 | 현재 관찰용 스냅샷으로만 사용 | 과거 백테스트 원본으로 혼합 |
| WebSocket `0B`·HTS 단발 조회 | 연결 종료 시 지수형 재연결. 8050·자격 증명 오류는 재연결하지 않음 | OAuth 성공 뒤의 현재 관찰·정규화 범위 | 과거 조건식 성과를 재구성하는 입력으로 사용 |
| 주문·계좌 변경성 요청 | 자동 재시도하지 않음 | 연구 전용 핵심 흐름에서 제외 | 실패를 새 주문으로 재전송 |

> 읽기 재시도는 현재 연구 데이터의 일시적 전달 실패를 다루는 장치일 뿐, 지정 단말 인증·토큰 발급·데이터 품질을 우회하지 않는다. `8050` 또는 고정 IP 미확인은 즉시 연결 대기 상태로 끝나며, OAuth가 성공한 뒤에만 일봉 수집과 데이터셋 준비를 순서대로 진행한다.

## 공식 명세 기준

키움 공식 REST 안내는 운영 도메인을 `https://api.kiwoom.com`, 모의투자 도메인을 `https://mockapi.kiwoom.com`으로 구분하고, OAuth 접근 토큰은 `POST /oauth2/token`에 `client_credentials`, `appkey`, `secretkey`를 JSON으로 전송하도록 명시합니다.[1] 이 프로젝트는 사용자의 요구에 따라 운영 도메인만 기본 경로로 사용합니다.

> 지정 단말 인증이 확인되기 전에는 OAuth·일봉·계좌·주문 브로커 요청을 실행하지 않는다. 화면은 예시 시장 데이터를 대체하지 않고 연결 대기·오류 상태만 표시한다.

## 아직 외부 검증이 필요한 항목

키움 REST API 측 지정 단말 허용이 실제 배포 출발지에서 확인돼야 OAuth 발급, 일봉 수집, 계좌 평가·잔고, 주문 체결 동기화를 실호출로 검증할 수 있습니다. 현재 자동 주문 전송은 이 인증과 별도 `KIWOOM_ORDER_TRANSMISSION_ENABLED` 승인 전까지 서버에서 차단됩니다.

개발 셸에서 관측한 공개 출발지 주소는 **배포 런타임의 고정 주소를 보장하지 않습니다**. 따라서 개발 셸에서 일시적으로 확인한 주소를 키움 지정 단말 정보로 등록해서는 안 되며, 배포 환경의 고정성·출발지 주소를 플랫폼 수준에서 확인한 뒤 등록해야 합니다.

### 사용자 접속 IP와 지정 단말 IP

공개 대시보드에 표시되는 `현재 접속 IP`는 그 순간 사이트를 여는 컴퓨터·휴대폰의 요청 IP다. 이 애플리케이션은 브라우저가 아니라 서버에서 키움 OAuth·일봉·계좌·주문 요청을 보내므로, 키움 지정 단말에는 **배포 서버의 고정 공인 출발지 IP**를 등록해야 한다. 사용자 기기 IP를 등록하는 방식은 로컬 컴퓨터에서 키움 API 프로그램을 직접 실행하는 경우에만 해당한다.

| 단계 | 실행 범위 | 주문 전송 |
|---|---|---|
| 개시 전 | 서버의 고정 공인 출발지 IP를 확인하고 키움 지정 단말에 등록 | 차단 |
| 1차 검증 | OAuth 토큰 발급만 읽기 전용으로 확인 | 차단 |
| 2차 검증 | `ka10081` 일봉과 `kt00018` 계좌 조회를 순차 확인 | 차단 |
| 3차 검증 | 조건 평가·랭킹·차트·백테스트의 실데이터 흐름 확인 | 차단 |
| 주문 준비 | 별도 전송 승인과 모든 주문 안전 한도를 다시 검증 | 계속 차단, 명시적 승인 뒤에만 허용 |

## WebSocket 범위

키움 공식 국내주식 안내는 WebSocket 엔드포인트를 운영 `wss://api.kiwoom.com:10000/api/dostk/websocket`, 모의 `wss://mockapi.kiwoom.com:10000/api/dostk/websocket`으로 구분하며, 모의 환경은 KRX만 지원한다고 명시합니다.[2] 실시간 항목으로 주문체결(`00`), 잔고(`04`), 주식시세(`0A`), 주식체결(`0B`), 주식호가(`0C`)와 조건검색 관련 TR(`ka10171`~`ka10174`)이 제공됩니다.[2]

그러나 구독·해제 메시지의 전체 스키마, 재연결 제한, 호출 한도는 현재 애플리케이션에서 실호출로 검증하지 않았습니다. 따라서 추측한 메시지 형식으로 연결하지 않으며, REST 일봉 기반 랭킹·차트·백테스트만 구현된 어댑터 범위로 유지합니다.

## tRPC 비JSON 응답 진단

개발 미리보기에서 서버 재시작·프록시 전환과 같은 일시적 상황이 발생하면 tRPC 요청이 JSON이 아닌 HTML 문서를 받을 수 있습니다. 기존 네트워크 로그에는 오류가 발생한 원래 procedure path와 HTML 본문이 항상 보존되지 않을 수 있으므로, 과거 오류만으로 근본 경로를 단정하지 않습니다.

현재 클라이언트 전송 계층은 비JSON 응답을 감지하면 `url`, HTTP `status`, `content-type`을 `[tRPC non-JSON response]` 콘솔 이벤트로 남기고, UI에는 JSON 파싱 예외 대신 구조화된 502 tRPC 오류를 반환합니다. 동일 현상이 재발하면 이 콘솔 이벤트의 `url`을 procedure path로 사용하고, `status`와 `content-type`을 서버·프록시 로그의 같은 시각 요청과 대조합니다.

### 과거 오류의 확인 결과

브라우저 콘솔 기록에는 `[vite] server connection lost. Polling for restart...` 직후 `Unexpected token '<'` tRPC 파싱 오류가 연속으로 남아 있다. 개발 서버 기록에는 재시작 중 `server/_core/trpcJsonFallback` 모듈을 찾지 못해 `ERR_MODULE_NOT_FOUND`로 중단된 구간이 확인된다. 개발 모드의 Vite 설정은 API 라우트에 도달하지 못한 미처리 요청을 SPA `index.html`로 반환하므로, 이 **재시작·모듈 오류 창에서 API 요청이 HTML 폴백을 받은 것**이 과거 오류의 확인 가능한 원인이다.

오래된 콘솔 이벤트에는 요청 URL·HTTP 상태·응답 헤더가 남지 않아, 당시의 개별 procedure path는 복구할 수 없다. 현재는 정상 서버에서 `/api/trpc/*` 미처리 경로가 JSON 404를 반환하는 통합 테스트와 비JSON 응답의 URL·상태·콘텐츠 유형 진단을 함께 유지한다. 따라서 동일 오류가 다시 발생하면 정확한 요청 경로까지 확보할 수 있다.

## 최근 읽기 전용 운영 검증 결과

주문 전송 플래그를 강제로 비활성화한 상태에서 운영 OAuth 토큰만 먼저 검증했습니다. 키움 운영 API는 `8050: 지정단말기 인증에 실패했습니다`를 반환했으며, 토큰을 받지 못했기 때문에 일봉·계좌평가 호출은 실행하지 않았습니다. 이 검증은 주문·자금 이동·체결 변경을 전혀 수행하지 않았습니다.

2026-08-13 사용자의 읽기 전용 재검증 승인 후에도 토큰 요청은 HTTP 200과 함께 `return_code=3`, `인증에 실패했습니다[8050:지정단말기 인증에 실패했습니다]`를 반환했고 접근 토큰은 없었습니다. 같은 실행 환경에서 외부로 관측된 출발지 IP는 `2.134.50.82`였으나, 이 값은 현재 샌드박스의 일시적 egress 관측값일 뿐 배포 런타임의 고정 IP를 보장하지 않습니다. 따라서 일봉(`ka10081`)·계좌·HTS 조건식 목록/현재 후보 호출은 순서상 실행하지 않았고, 주문 전송은 계속 차단 상태입니다.

2026-08-14 사용자로부터 지정 단말 등록 완료 통지를 받은 뒤, 주문·계좌 조회 없이 운영 OAuth 토큰 발급만 다시 요청했습니다. 응답은 다시 HTTP 200, `return_code=3`, `8050:지정단말기 인증에 실패했습니다`였고 접근 토큰은 발급되지 않았습니다. 이 결과는 현재 검증 런타임의 실제 출발지 IP가 키움 지정 단말 등록 정보와 일치하지 않거나 등록 상태가 아직 운영 API에 반영되지 않았음을 의미할 수 있으나, 응답만으로 둘 중 어느 원인인지는 확정할 수 없습니다. 토큰이 없으므로 `ka10081` 일봉·데이터셋·백테스트 호출은 실행하지 않았으며, 주문 전송도 수행하지 않았습니다.

2026-08-15 자동 결과 화면에서 두 독립 egress 확인 서비스가 `162.220.234.68`로 일치해 이 값을 지정 단말 등록 대상으로 표시했습니다. 사용자 등록 완료 통지 뒤 다시 주문·계좌 조회 없이 운영 OAuth 토큰 발급만 실행했으나, 응답은 여전히 HTTP 200, `return_code=3`, `인증에 실패했습니다[8050:지정단말기 인증에 실패했습니다]`였고 접근 토큰은 없었습니다. 따라서 서버 egress 확인값과 키움 OAuth 요청의 실제 출발지 경로가 반드시 같다고 단정할 수 없으며, 키움 측 등록 반영·고정 egress 보장 여부를 추가로 확인하기 전에는 일봉·후보 평가·모의 추적을 실행하지 않습니다.

같은 날 최종 공개 배포 도메인의 `키움 연결 확인`은 OAuth 접근 토큰 발급 성공과 만료 예정 시각을 표시했습니다. 반면 개발 검증 환경에서 별도로 실행한 주문 없는 `ka10081` 일봉 검증은 토큰 발급 단계에서 다시 `8050`을 받았습니다. 이는 개발 검증 환경과 공개 배포 서버의 키움 요청 출발지 경로가 다름을 보여준다. 따라서 실제 일봉·자동 리서치 운영 검증은 OAuth 성공이 확인된 **공개 배포 서버의 장중 자동 작업**에서만 수행하며, 개발 셸의 8050 결과를 공개 배포 서버의 인증 실패로 해석하지 않습니다.

따라서 앱은 지정 단말 인증이 실제로 성공하기 전까지 실데이터 수집 결과를 만들지 않고 연결 대기 상태를 표시해야 합니다. 주문 전송은 별도 전송 승인, 최종 확인, 매수 상한, 일일 한도와 킬 스위치가 모두 통과해야 하는 기존 안전 게이트로 계속 차단됩니다.

## 공개 사이트의 OAuth 연결 확인

공개 자동 리서치 대시보드는 `키움 연결 확인` 동작을 제공한다. 이 동작은 사용자의 키움 ID·비밀번호를 브라우저에서 입력하거나 사용자의 휴대폰·컴퓨터 IP로 인증하는 기능이 아니다. 배포 서버가 이미 비밀 저장소에 보관된 App Key·App Secret으로 OAuth 접근 토큰을 요청하고, 브라우저에는 `connected` 또는 `waiting` 상태·안전한 안내 문구·토큰 만료 예정 시각만 반환한다. App Key·App Secret·접근 토큰 원문은 응답과 화면 어느 곳에도 포함하지 않는다.

공개 클릭에 따른 반복 OAuth 요청을 제한하기 위해 서버는 진행 중인 확인을 하나로 합치고, 완료된 결과를 2분 동안 재사용한다. `8050` 지정 단말 오류는 키움 원문을 그대로 확장 노출하지 않고 지정 단말 인증 대기 상태로 정규화한다. 이 확인이 성공해도 주문·계좌 조회는 실행하지 않으며, 자동 실데이터 수집은 기존 장중 작업 수명주기에서만 재개한다.
