# 진화형 조건식 탐색 실행 경계

## 기본 웹 연구 배치

웹 요청에서 생성하는 진화형 세대는 **10~100개 후보**로 제한한다. 각 후보는 고정된 실제 일봉, 비용·체결·정보 절단 가정, 후보 지문을 함께 기록한다. 요청이 끝나면 세대와 후보가 데이터베이스에 남으므로, 사용자는 개별 후보를 평가한 뒤 생존자만으로 다음 세대를 만들 수 있다.

이 경계는 브라우저 요청이 장시간 계산을 수행하거나 중간 실패 뒤 상태를 잃지 않게 하기 위한 것이다. `ready` 실제 데이터셋이 없거나 OAuth로 실제 원본을 수집하지 못한 환경에서는 생성·평가 결과를 만들지 않는다.

## 1,000개 이상 세대 탐색

1,000개 이상 후보를 여러 세대 반복 평가하는 탐색은 웹 요청으로 실행하지 않는다. 별도 지속 실행 환경에서 다음과 같은 작업 단위로 수행한다.

| 경계 | 실행 원칙 | 기록 항목 |
|---|---|---|
| 작업 단위 | `searchId + generationId + symbol` 조합을 재시도 가능한 작업으로 분리한다. | 시작·종료 시각, 시도 횟수, 오류 요약 |
| 동시성 | 같은 토큰의 실제 일봉 수집은 200ms 이상 간격을 유지한다. 이미 고정된 원본 평가에는 CPU·메모리 상한을 둔다. | 큐 깊이, 처리 후보 수, 실패 수 |
| 재시도 | 원본 수집 실패와 후보 평가 실패를 분리한다. 실패 후보는 결과를 추정하지 않고 `error` 상태로 남긴다. | 오류 코드, 후보 지문, 재시도 횟수 |
| 중복 방지 | 탐색 단위의 유전자 지문 고유 제약을 유지하고, 같은 세대 재개 시 기존 후보를 다시 만들지 않는다. | 지문, 세대, 부모 후보 ID |
| 중단·복구 | 세대 전체가 아닌 후보 단위로 체크포인트를 남긴 뒤 중단 지점부터 재개한다. | 마지막 완료 후보, 세대 상태 |

## 실행 방식 선택

| 방식 | 적합한 목적 | 장점 | 제약 |
|---|---|---|---|
| 웹 연구 배치 | 가설 확인, 10~100개 후보의 규칙·파라미터 점검 | 즉시 결과를 검토하고 상세 규칙·계보를 확인 | 대량 세대 반복에는 부적합 |
| 지속 실행 탐색 | 1,000개 이상 후보, 수십 세대 반복, 다종목 워크포워드 | 장기 작업·재시도·체크포인트 처리 가능 | 고정 실제 데이터와 별도 실행 환경이 필요 |

> 대규모 탐색은 높은 수익률을 보장하지 않는다. 인샘플 선발 후보는 반드시 독립 워크포워드에서 다시 평가하며, 평가 전의 미래 봉·비용·체결 가정을 사용하지 않는다.
