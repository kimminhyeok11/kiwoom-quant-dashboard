# 키움 HTS 저장 조건식 연동 설계

## 목적과 비밀정보 경계

사용자가 영웅문4에서 이미 만든 조건검색식은 **키움 OAuth 인증이 성공한 서버 세션에서만** 목록 조회와 실행 대상으로 사용한다. 사용자 키움 로그인 ID·비밀번호·인증서 비밀번호는 애플리케이션에 입력·전송·저장하지 않는다. 서버에는 기존과 같이 키움 Open API App Key·App Secret과 OAuth 접근 토큰만 존재하며, 브라우저에는 그 값을 반환하지 않는다.

## 공식 API 계약

키움 공식 문서는 조건검색식을 영웅문4에서 만들 수 있으며, WebSocket `wss://api.kiwoom.com:10000/api/dostk/websocket`에서 `CNSRLST` 메시지로 조건식 목록을 받는다고 정의한다. 목록에는 조건식 일련번호 `seq`와 이름 `name`이 포함된다. [1]

일반 조건검색 실행은 같은 WebSocket에서 `CNSRREQ` 메시지로 수행한다. 실행 전에는 조건검색 목록조회(`ka10171`)가 선행되어야 하며, 목록에서 받은 `seq`가 필요하다. 응답은 현재 조건을 만족하는 종목코드·종목명·현재가·등락률·누적거래량 등의 스냅샷과 연속조회 키를 제공한다. [2]

공개 API 문서는 조건검색 WebSocket의 엔드포인트·메시지·OAuth 인증 필요 여부를 표시하지만, Node 서버 WebSocket 업그레이드에서 OAuth 접근 토큰을 전달하는 구체적 헤더·서브프로토콜·초기 인증 메시지 형식은 현재 공개 본문에서 확인되지 않았다. 따라서 앱은 접근 토큰을 서버 내부 `RealtimeTransportFactory` 경계에만 전달하고, 실제 형식은 지정 단말 인증이 정상화된 뒤 **주문 없이** `CNSRLST` 목록 조회의 성공 응답으로 확정한다. 추정한 인증 형식은 주문·계좌·실시간 조건감시에 사용하지 않는다.

| 기능 | 공식 TR / 메시지 | 앱의 처리 원칙 |
|---|---|---|
| HTS 저장 조건식 목록 | `ka10171` / `CNSRLST` | 운영자 전용, OAuth 성공 후 수동 조회 |
| 현재 조건 충족 종목 조회 | `ka10172` / `CNSRREQ` | 목록에서 선택한 `seq`만 실행, 현재 후보를 차트·유니버스 입력으로 사용 |
| 조건편입 실시간 감시 | `ka10173` | OAuth·WebSocket 실연결 검증 후 별도 명시적 시작/해제 제어 |
| 조건 실시간 해제 | `ka10174` | 페이지 이탈·운영자 중지·오류 시 해제 |

## 백테스트의 적용 한계

`ka10172`는 호출 시점의 조건검색 결과를 제공하는 API이므로, 과거 각 거래일에 해당 HTS 조건식이 포착했던 종목 이력을 자동으로 제공하는 계약은 아니다. 따라서 기존 HTS 조건식으로 **과거 성과를 재현하는 백테스트**는 다음 둘 중 하나로 처리한다.

1. 조건의 기술적 논리를 앱의 영웅문형 조건 빌더로 동일하게 재구성하고, 일봉 시계열에서 일자별로 평가한다.
2. OAuth 연결 성공 후 조건검색 결과를 일자·시각과 함께 수집·저장하여, 이후부터는 실제 후보 이력을 기반으로 워크포워드 분석한다.

현재 단계에서는 첫 번째 방식이 기존 저장형 백테스트에 이미 적용되어 있고, 두 번째 방식은 WebSocket 실연결과 지정 단말 인증이 성공한 뒤에만 활성화한다. 현재 조건검색 결과를 백테스트에 사용할 때에는 과거 조건 충족 사실로 오인하지 않도록 **“현재 후보 유니버스”**로 표시한다.

## 사용자 흐름

1. 운영자가 앱의 OAuth 연결 상태가 `발급됨`인지 확인한다.
2. “HTS 조건식 불러오기”를 수동으로 실행해 `seq`와 이름 목록을 조회한다.
3. 조건식을 선택해 현재 후보 종목을 조회한다.
4. 후보를 종목 차트·조건 평가 또는 일봉 백테스트의 유니버스로 명시적으로 전달한다.
5. 실시간 감시는 별도의 시작 확인·중지 제어를 거쳐 사용하며, 주문 실행과 자동으로 연결하지 않는다.
