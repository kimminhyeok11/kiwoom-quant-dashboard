# 실제 데이터 연구 API 호출·토큰 정책

## 적용 범위

이 서비스는 **실제 일봉 데이터셋을 한 번 수집해 버전 단위로 고정하고, 같은 원본으로 조건식 실험과 워크포워드를 재실행**하는 리서치 도구다. 주문, 계좌, 체결, 실시간 감시, HTS 후보 수집은 이 정책의 적용 대상이 아니다.

## 키움 공식 경계

키움 REST API 소개는 국내주식 조회 TR을 계좌별(토큰별) **초당 5회**로 제한한다. 접근 토큰 발급 API는 `POST /oauth2/token`이며 응답의 `token`과 `expires_dt`를 반환한다. 따라서 데이터셋 수집은 토큰을 요청마다 새로 발급하지 않고, 서버에서 만료 전 캐시한 동일 토큰을 재사용해야 한다.[1] [2]

| 통제 항목 | 연구 서비스 정책 | 목적 |
|---|---|---|
| 데이터 요청 | 수집 실행 중 종목·페이지를 순차 처리하고, 자동 폴링을 하지 않는다. 서버의 토큰 공유 요청 조절기는 일봉 조회를 최소 200ms 간격으로 예약한다. | 토큰별 초당 5회 조회 한도 내에서 원본을 고정한다. |
| 재수집 | `draft` 데이터셋만 최초 수집한다. `ready` 원본은 갱신하지 않고 새 버전 키로 별도 생성한다. | 기존 실험의 재현성을 보전한다. |
| 토큰 재사용 | 서버 캐시 토큰을 사용하고 `expires_dt` 이전에만 재발급한다. | 불필요한 OAuth 호출을 피한다. |
| 실패 처리 | OAuth 또는 일봉 호출이 실패하면 데이터셋을 `error`로 기록하고, 결과·수익률을 생성하지 않는다. | 예시·추정 시장 데이터의 혼입을 막는다. |
| 외부 인증 | 지정 단말 인증이 성공하기 전에는 수집을 실행할 수 없다. 현재 환경의 8050 실패는 데이터 없음으로만 처리한다. | 외부 증권사 보안 경계를 우회하지 않는다. |

> 공식 한도는 **토큰별** 조회 기준이다. 여러 수집 요청이 동시에 시작될 수 있으므로, 일봉 조회에는 프로세스 내 토큰 공유형 요청 조절기를 적용해 최소 200ms 간격을 보장한다. 실제 운영 수집은 OAuth 성공 뒤에도 이 간격과 키움의 응답을 읽기 전용으로 재검증한다.

## 검증 상태

2026-08-13의 승인된 읽기 전용 운영 OAuth 검증은 `8050 지정단말 인증 실패`로 토큰 발급 전에 중단되었다. 이 때문에 실제 `ka10081` 수집 속도 검증은 아직 수행되지 않았고, OAuth 성공 및 고정 출발지 환경이 준비된 뒤 **주문 없이** 재검증한다.
