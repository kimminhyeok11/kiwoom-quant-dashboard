# 조건식 리서치 워크스페이스 제공 상태

## 제공 범위

이 서비스의 제1 목적은 **실제 일봉·분봉 데이터로 조건식 가설을 재현 가능하게 평가하는 연구 워크스페이스**다. 검증된 생존 조건식은 별도의 사용자 컴퓨터 로컬 실행기에서 키움 모의투자 주문 계획·체결 동기화로 추적할 수 있지만, 이는 연구 결과와 분리된 보조 운영 경로다. 실제 시장 수치가 아직 연결되지 않은 경우에는 결과를 만들거나 예시 가격을 보여 주지 않고, 데이터 연결 대기 상태만 표시한다.

|---|---|---|
| 영웅문형 조건식 편집 | 완료 | 규칙·기간·단위·비교 연산·가중치·AND/OR/NOT 트리 |

## 외부 검증 보류의 의미

키움 OAuth와 `ka10081` 일봉 요청은 브라우저나 휴대폰이 아니라 **애플리케이션 서버**에서 전송한다. 따라서 키움 지정 단말에는 사이트 방문 기기의 IP가 아닌, 해당 서버가 실제로 사용하는 **고정 공인 출발지 IP**가 등록되어야 한다. 키움 운영 OAuth는 `client_credentials` 방식으로 App Key와 Secret을 서버에서만 전송하도록 안내된다.[1]

현재 검증 런타임에서는 운영 OAuth가 HTTP 200과 함께 `8050` 지정단말 인증 실패를 반환해 접근 토큰이 발급되지 않았다. 토큰이 없으므로 순서상 일봉·계좌·HTS WebSocket·조건 평가 실행은 중단한다. 이는 기능 미구현이 아니라 외부 증권사 인증 경계가 아직 이 런타임을 허용하지 않은 상태다. 주문 전송은 이 흐름에서 제외되며, 별도 승인과 안전 게이트 없이는 허용되지 않는다.

2026-08-17 읽기 전용 재진단에서 방문 기기 화면에는 `79.127.228.18`이 표시되어 이 값이 키움 App Key 관리에 등록된 것을 확인했다. 그러나 실제 배포 서버의 외부 출발지 IP는 같은 시점에 `162.220.234.153`으로 조회됐고, 배포 서버에서 요청한 OAuth 확인은 다시 `8050` 지정단말 인증 실패를 반환했다. 따라서 등록 대상은 방문 기기 IP가 아니라 배포 서버 출발지 IP이며, 해당 출발지의 고정성은 별도 운영 환경에서 확인이 필요하다.

> 휴대폰으로 웹사이트에 접속하거나 휴대폰 IP를 등록해도 서버가 보내는 키움 API 요청의 출발지 IP는 바뀌지 않는다. 휴대폰 IP는 화면 접속에만 쓰이며, 배포 서버의 API 인증을 대체하지 않는다.

### 2026-08-18 재시도 기록

2026-08-18 07:39 KST에 공개 읽기 전용 과거 백테스트를 다시 요청했다. 해당 시점 공개 화면의 서버 출발지 IP 표시는 `152.55.180.121`이었고, 신규 요청은 주문·계좌·포지션 호출 없이 OAuth 단계에서 `8050` 지정단말 인증 실패로 종료됐다. 따라서 새 `ka10081` 원본 수집·장중 가격 관찰 입력은 시작되지 않았으며, 기존의 실제 일봉 원본을 새 데이터인 것처럼 표시하지 않았다.

같은 배포에서 `ka10032` 거래대금 순위가 비어도 최근 완료된 실제 연구의 유니버스를 `ka10081` 수집 대상으로 복원하는 폴백을 배포했다. 현재 순위가 존재하면 순위를 우선하며, 드라이버가 유니버스 JSON을 배열 또는 문자열로 반환하는 두 경우를 모두 처리한다. 218개 회귀 테스트와 TypeScript 검사를 통과했다. 다만 이번 재시도는 OAuth 단계에서 중단되어 폴백의 외부 호출 구간은 아직 재검증 대기다.

외부 호출 없이 저장된 실제 일봉을 재사용한 연구 실행은 2026-08-18 07:41 KST에 완료됐다. 실행 `120002`는 원본 실행 `1`의 실제 조정 일봉 12,000개·20종목을 사용해 조건식 100개를 다시 평가했고, 12개 생존 후보와 독립 OOS·워크포워드 결과를 저장했다. 직전 배포 중단으로 남은 실행 `120001`은 `incomplete`로 멱등 복구됐으며, 새 실행은 `completed · ready` 상태를 기록했다.

### 2026-08-18 실제 주문 연동 점검

실투자 주문 전송은 이 문서의 연구 운영 범위에서 제외한다. 현재는 사용자 승인에 따른 키움 **모의투자** 경로만 로컬 실행기에 활성화했으며, 총자본 1,000만 원·최대 5종목·손절 2%·익절 3%·일일 손실 3% 정책과 중복 키·킬 스위치·손실 차단을 적용한다. 실제 모의 API 주문번호·체결·미체결·포지션 동기화의 다음 장중 운영 검증은 별도 작업 목록에서 추적한다.

키움 공식 안내에 따르면 Open API는 고객이 작성한 전략을 키움 모듈에 연결해 시세·잔고·주문을 처리하는 서비스이며, 당사 계좌와 HTS ID 연결이 사용 요건이다.[1] 이 서비스의 REST API 주문은 지정된 같은 키움 계좌의 주문으로 전송되므로, 정상 전송·체결된 주문은 영웅문 앱에서도 해당 계좌의 주문·체결·보유종목 기록으로 확인하는 구조다. 다만 웹 서비스는 영웅문 앱 화면을 원격 조작하거나 앱의 화면 상태를 읽지 않는다. 영웅문 저장 조건식은 별도 조건검색 API 범위이며, 현재 리서치 조건식·당일 모의투자 기록과는 원본과 평가 목적을 분리한다.

## 게시 완료와 운영 검증의 분리

자동 리서치 서비스의 구현과 게시에는 배포 서버 고정 IP 인증의 실측 성공이 필요하지 않다. 게시된 서비스는 사용자 로그인·수동 조건식 설정·수동 실행 없이 거래 시간 단계에 따라 자동으로 후보를 생성하고, 실제 데이터가 준비될 때에만 모의 추적과 성과 기록을 이어 간다. 사용자 컴퓨터의 지정 IP 연구 노드는 별도로 실제 일봉·분봉 수집과 모의 주문 실행을 맡는다. 인증이 아직 준비되지 않은 동안에는 기존 구현을 변경하거나 가상 시장 데이터를 만들지 않고 `waiting_for_data` 상태를 유지한다.

따라서 고정 IP·OAuth·일봉 수집 검증은 **게시 후 별도 운영 절차**다. 인증이 가능한 환경이 마련되면 위의 읽기 전용 재개 절차를 수행할 뿐, 자동 리서치 화면·후보 생성·백테스트·OOS·워크포워드·상시 실행 구조를 다시 개발할 필요는 없다.

## 검증 재개 절차

고정 egress IP가 확보되고 그 값이 키움 지정 단말에 반영된 뒤, 주문 없이 아래 순서만 수행한다. 각 단계가 성공하기 전에는 다음 단계로 진행하지 않는다.

| 단계 | 읽기 전용 작업 | 성공 기준 | 실패 시 조치 |
|---|---|---|---|
| 1 | 운영 OAuth 토큰 발급 | 접근 토큰과 만료 시각 수신 | 8050·자격 증명 오류를 기록하고 중단 |
| 2 | `ka10081` 일봉 수집 | 정규화된 일봉 원본 수신 | 빈 응답·TR 오류를 기록하고 중단 |
| 3 | 데이터셋 준비 | 가격 기준·유니버스·기간이 고정된 `ready` 데이터셋 | 품질 상태를 오류로 기록 |
| 4 | 조건식 연구 실행 | 조건 평가, 백테스트, 독립 OOS, 워크포워드 결과 저장 | 해당 실험만 실패로 기록 |

키움은 운영 REST와 WebSocket 엔드포인트를 구분하며, 모의 WebSocket은 KRX만 지원한다고 안내한다.[2] 현재 서비스의 핵심 연구 경로는 고정 일봉 데이터와 앱 내부 조건식이므로, HTS 현재 후보나 실시간 수신값을 과거 백테스트 원본으로 혼합하지 않는다.
