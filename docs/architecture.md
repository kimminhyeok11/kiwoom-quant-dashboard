# 키움 퀀트 대시보드 아키텍처

## 핵심 흐름

사용자는 조건 프리셋을 구성하고 백테스트 또는 모의매매로 결과를 검증한다. 랭킹 작업은 거래대금 상위·조건검색·일봉 데이터를 입력으로 조건 엔진을 수행해 점수를 산출한다. 주문 후보는 즉시 주문되지 않으며, 위험 제한을 통과한 뒤 사용자 확인이 담긴 `order_intents` 레코드로 생성된다. 사용자가 해당 의도에 대한 확인을 완료한 경우에만 주문 어댑터가 키움 주문 요청을 전송한다.

## 데이터 경계

`strategy_presets`는 조건 구성과 점수 가중치를, `trading_profiles`는 모의/실거래 환경·갱신 주기·위험 한도를, `ranking_snapshots`는 계산된 랭킹 결과를 보관한다. `backtest_runs`는 시뮬레이션의 재현 가능한 설정과 결과를 기록한다. `order_intents`와 `order_executions`는 확인과 API 응답을 분리해 감사 추적을 제공하며, `position_snapshots`는 조회 시점의 계좌 상태를 보관한다.

## 주문 안전 불변 조건

| 제어 | 적용 시점 | 차단 기준 |
| --- | --- | --- |
| 모드 차단 | 주문 후보 생성 전 | 모의 모드가 아니면서 연결 검증이 없는 경우 |
| 킬 스위치 | 주문 후보 생성 전·확인 전 | 자동매매가 비활성화된 경우 |
| 단일 주문 한도 | 주문 후보 생성 전 | 주문 금액이 최대 매수 금액을 초과한 경우 |
| 일일 거래 한도 | 주문 후보 생성 전 | 당일 확인·전송된 주문 수가 한도 이상인 경우 |
| 필수 확인 | 주문 전송 직전 | 확인 토큰 또는 확인 시각이 없는 경우 |
| 중복 방지 | 주문 전송 직전 | 동일 의도가 이미 전송/체결 상태인 경우 |

모든 주문 전송은 서버에서만 이루어지며, App Secret과 Bearer 토큰은 브라우저로 전달하지 않는다.
